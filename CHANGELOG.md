# Changelog

All notable changes to **figforge** are documented here. Each entry tracks one Figma Desktop client release; the app itself remains Figma Desktop, with Figma's name, icon and interface unchanged.

## [126.12.7-r2] — 2026-11-23

Build-only revision of `126.12.7`; no change to the Figma client, Electron or Chromium. Artifact checksums were verified from the published release.

| Artifact | SHA-256 |
| --- | --- |
| AppImage | `c9c8bc6f9ecb40d34a22b1ce7b8a139b7ebc722290cb5b500110eb3dfbadf7b2` |
| deb | `6a1417f8940b25b51ec8ed15d52bf4cbeb4b591c9f020a91d9fe5bc9eaf53406` |
| rpm | `09ed48ef9ec1cc95f411dad0572faa62c683f1148ebfd0ee67de169cd9c281bc` |

### Fixed

- **Desktop-entry upgrade path** — entries generated by figforge before `r1` carried no `X-Figforge-AppImage=` marker, so the new launcher treated them as user-managed and left them pointing at the previous AppImage. Such entries are now recognised by their unchanged `Comment`/`StartupWMClass` signature, migrated once to the current path, and given the marker. Custom `Exec` flags are still preserved; genuinely user-owned entries remain untouched.
- Removed the inherited upstream Telegram/OpenClaw workflow, which failed on every issue and discussion event because figforge has neither the secrets nor the self-hosted runner it requires.

## [126.12.7-r1] — 2026-11-23

Rebuild of the `126.12.7` client with two Phase 4 fixes. The Figma client, Electron and Chromium versions are unchanged from [126.12.7]; only the figforge build/launcher code differs. Artifact checksums were verified from the published release.

| Artifact | SHA-256 |
| --- | --- |
| AppImage | `b47868013d3723e274e464ecf245f88e87c5b58f9cfa98e13aee0fb1906a8c5f` |
| deb | `c247428ae8b7410a508d42e5c7d69c8e7e90443ddf93c2523f47d6cf8c7a8073` |
| rpm | `36856301503d79e6db4fdc76bb9398b756632585b2184dc138ea91be82f9cf0e` |

### Fixed

- **B9 / upstream #32** — the AppImage no longer rewrites `~/.local/share/applications/figma-desktop-appimage.desktop` on every launch. The generated entry now carries an `X-Figforge-AppImage=` marker; user-edited `Exec` flags (e.g. `--enable-features=Vulkan,WebGPU`) survive restarts and are preserved when the AppImage path changes. A file without our marker is treated as user-managed and left alone.
- **B5 / upstream #36** — the tray icon follows the system light/dark theme on Linux. Figma gated both `isSystemDarkMode()` and the `nativeTheme` update listener behind `process.platform === "win32"`; the build now drops that gate while keeping the existing Linux stub implementation.

## [126.12.7] — 2026-11-23

First tracked release of the maintained fork. The `RELEASES` manifest still advertised `126.11.11`, so the build used the installer-embedded NuGet package as the version authority (see [MAINTENANCE.md](MAINTENANCE.md)).

### Client versions

| Component | Version |
| --- | --- |
| Figma Desktop | `126.12.7` |
| Electron | `44.11.3` (auto-detected from `Figma.exe`) |
| Chromium | `152.0.7977.169` |
| `@electron/asar` (build pin) | `4.2.0` |

### Added

- Continuous-development documentation: [ROADMAP.md](ROADMAP.md), [MAINTENANCE.md](MAINTENANCE.md), [ATTRIBUTION.md](ATTRIBUTION.md).
- Fail-loud patch sentinels for the native-frame, title-bar, Linux menu and `shell.html` injection targets.
- `scripts/tests/patch-sentinels.test.js` — 7 regression tests that guard the guards.
- Linux argv handling is now detected upstream; the legacy patch is skipped automatically when Figma ships native support.
- Tray context-menu patch now accepts both the legacy null-check and the modern `this.electronTray?.popUpContextMenu(...)` shape.

### Fixed

- Bare `"` characters inside bash `node -e "..."` blocks were stripped by the shell, so the tray-window and selector regexes never matched. Embedded quotes are now escaped.
- The tray-window, argv and tray-context patch blocks warned and continued on no-match. They now call `process.exit(1)` and the build propagates failure with `|| exit 1`.
- `patch_app_asar` failure now aborts the build instead of producing a silently broken client.

### Known issues

- Interactive sign-in/logout, fonts, `figma://`, MCP, tray menu and drag-and-drop need a human session; not covered by automated checks.
- Wayland visual regressions #29 (tab bar) and #34 (app-view blanking) were not visually confirmed — no working screenshot portal in the test context.
- Issue #23 (canvas corruption on Fedora 44 / Mesa 26) expected to be resolved by Chromium 152, not yet verified.
- Users on builds older than June 2026 should upgrade before Figma's **15 December** support cutoff. This release tracks the current client; the December notice shown by older builds is a real server-side version gate, so it is deliberately not hidden by a UI patch.
